# 飞书库存表标准化迁移方案

记录日期：2026-08-28

## 已确认方向

不直接在旧表中批量覆盖全部历史数据，而是在现有“指环库存管理”和“腕表库存管理”多维表格应用内分别创建标准化新表组，将旧表历史记录清洗并导入新表。旧表在切换后转为只读归档。

全部旧表历史出入库记录及当前库存已确认属于余杭仓，迁移时统一赋予余杭仓稳定仓库 ID。西湖仓不复制历史余额，初始库存为零，后续通过调拨、正式入库或盘点流水建账。

## 推荐新表组

每个商品大类的现有多维表格应用内至少建立：

- 产品资料表：稳定产品 ID、正式名称、历史别名、主图、详情图、是否启用。
- 仓库库存余额表：仓库、产品、可选尺码、现存数量、同步版本。
- 库存流水表：业务单号、仓库、产品、可选尺码、变动类型、数量、前后余额、操作人、时间、来源和幂等键。

申请主单、申请明细、审核和同步任务的最终存放边界在技术设计阶段确定；本地数据库负责事务和工作流，飞书保留最终库存余额与完整库存流水。

## 历史迁移字段

- `source_table_id`
- `source_record_id`
- `source_name_snapshot`
- `migration_batch_id`
- `migrated_at`
- `product_id`
- `warehouse_id`
- `business_id`
- `idempotency_key`

## 迁移步骤

1. 使用 `lark-cli` 只读导出现有应用、表、字段、视图和全部记录清单。
2. 为旧表和导出文件生成受保护快照与记录数/数量基线。
3. 创建标准化新表和字段，不删除旧表。
4. 按历史别名映射正式产品，统一补充余杭仓稳定 ID，并补齐来源字段。
5. 使用可重复执行的迁移批次导入新表。
6. 核对源/目标记录数、产品尺码数量合计、出入库合计和当前余额。
7. 在测试查询和同步通过后切换网页表映射。
8. 将旧表改为只读归档，新业务只写新表。

## 回滚与审计

- 旧表始终保留迁移前数据和字段，不作为新业务写入目标。
- 每条新记录可以追溯到旧表和旧记录。
- 迁移脚本使用稳定幂等键，重复执行不产生重复数据。
- 验收失败时可将网页映射切回旧表，并修复新表后再次迁移。
- 禁止在无快照、无迁移报告或未核对余额时直接切换。
- 西湖仓不得通过复制余杭历史余额初始化；任何西湖初始数量必须有对应调拨、入库或盘点流水。

## 腕表历史产品口径

2026-08-31 已确认：`玫瑰`、`满天星`、`黑金` 分别作为独立的历史停用腕表产品迁移，当前余杭仓库存基线为 27、42、68 件。

- 不建立到 `健康腕表` 的别名映射，不合并库存。
- 新产品资料记录标记为历史停用，库存查询可见，所有申领入口不可选择。
- 历史入库记录和余额均绑定各自稳定产品 ID，并保留旧表、旧记录及原始名称。
- 后续重新归类必须走有流水的盘点调整或专门迁移批次，不直接覆盖历史产品 ID。
