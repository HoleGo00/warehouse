# 仓储领用与飞书库存同步 V1 实施计划

> 2026-08-31 起，本文件作为总 Epic 的总体实施基线；实际开发按 [task-map.md](./task-map.md) 中的九个子任务严格串行推进。任何时刻只允许一个子任务进入 `in_progress`，后续子任务在前置任务完成验收前保持 `planning`。

## 1. 实施原则

- 先完成本地系统、自动化测试和迁移 dry-run，再对真实飞书 Base 执行增量写入。
- 不删除、不重命名任何现有表和字段；禁止直接改旧台账余额。
- 所有真实飞书操作统一通过固定版本 `lark-cli@1.0.91`，写前读取、dry-run，写后定向回读。
- 每个阶段必须通过本阶段测试和 `git diff --check` 后才能进入下一阶段。
- 项目尚未初始化 Git；实施开始时先建立版本基线，迁移快照、密钥和 CLI profile 不提交仓库。

## 2. 有序实施清单

### Phase A：工程与规范基线

- [ ] 初始化 Git、pnpm workspace、Node/TypeScript 工具链和基础 `.gitignore`。
- [ ] 建立 `apps/web`、`apps/api`、`apps/worker` 与共享 packages。
- [ ] 配置 ESLint、Prettier、Vitest、Playwright、类型检查和统一构建命令。
- [ ] 按真实脚手架补全 `.trellis/spec/frontend`、`.trellis/spec/backend` 的项目规范。
- [ ] 提供本地开发 Docker Compose（PostgreSQL）和 `.env.example`，不写入真实密钥。

验证：安装、lint、typecheck、最小单测、web/api/worker 构建全部通过。

### Phase B：数据库与核心领域

- [ ] 建立 Prisma schema、首个迁移和种子：两仓、三角色、10 款指环、健康腕表、三个历史停用腕表、6# 至 13# variant。
- [ ] 实现用户/角色/仓库授权、商品、库存余额、预占、流水、领用主明细、审核、归还、管理员任务、审计、outbox、飞书映射和对账表。
- [ ] 实现事务封装、固定顺序行锁、请求幂等和库存计算服务。
- [ ] 为整单成功、整单失败、并发超卖、重复请求和调拨守恒编写数据库集成测试。

验证：数据库迁移可前进/回滚；并发测试证明不会超卖或留下部分流水。

### Phase C：飞书登录与 RBAC

- [ ] 配置飞书 OAuth/客户端免登回调、租户校验、应用可用范围校验和本地会话。
- [ ] 实现首次普通用户创建和首位系统管理员一次性初始化。
- [ ] 实现仓库管理员多仓授权及所有仓库 API 的服务端权限守卫。
- [ ] 接入离职事件/状态同步并生成待归还任务，不自动回库。
- [ ] 添加登录回跳仓库上下文、外租户拒绝、越权仓库访问和重复初始化测试。

验证：普通员工、单仓管理员、双仓管理员和系统管理员权限矩阵全部通过。

### Phase D：商品、图片、库存查询与二维码

- [ ] 实现商品/variant 管理、ACTIVE 主图必填、历史停用产品只读库存展示。
- [ ] 实现 `lark-cli` 附件上传/下载 Gateway 和短时图片代理缓存。
- [ ] 实现两仓库存查询、两仓汇总、指环矩阵、腕表列表及待同步标识。
- [ ] 实现西湖/余杭稳定入口和二维码下载；登录后保持仓库锁定。
- [ ] 完成桌面管理端和移动扫码页面的响应式视觉验收。

验证：历史停用腕表库存可见但任何新增领用选择接口均不返回；无主图的 ACTIVE 产品不能启用。

### Phase E：正常、临时与线下领用

- [ ] 正常领用：提交、退回、整单审核预占、取消预占、整单发放。
- [ ] 临时领用：最小字段立即出库、3 个工作日截止、补手续、退回补正、后补审核。
- [ ] 线下登记：授权管理员完整代录、直接整单出库。
- [ ] 实现混领 UI：指环款式尺码矩阵 + 腕表产品数量，共享一套主单信息。
- [ ] 实现用途/归还条件动态校验和管理员待办。
- [ ] 覆盖库存不足、部分商品失败、重复提交、审核后库存变化、同步失败等集成测试。

验证：三类流程与 PRD 状态、库存时点和整单规则一致。

### Phase F：完整库存业务

- [ ] 实现采购/其他入库、实物归还、两仓调拨、盘点盘盈/盘亏。
- [ ] 实现待归还日期扫描、离职触发和实物回库确认。
- [ ] 所有入口只调用统一库存事务服务，不存在直接修改余额 API。
- [ ] 验证调拨一出一入总量守恒、归还不提前入库、盘点必须有原因与审计。

### Phase G：PostgreSQL outbox 与 lark-cli 同步

- [ ] 建立 CLI 子进程白名单、JSON 输入、超时、输出上限、错误分类和脱敏日志。
- [ ] Worker 实现 `SKIP LOCKED` 领取、租约、指数退避、人工幂等重试和死信/人工处理状态。
- [ ] 实现指环/腕表 Base 子任务、流水存在性检查、余额 record ID 映射、定向回读。
- [ ] 实现混领部分同步状态和管理员同步异常页面。
- [ ] 使用新建测试表验证 `--as bot`、字段创建、记录批量写入、更新、附件和回读；不触碰旧表。

验证：模拟 CLI 超时、限流、权限失败、进程重启和重复任务，均不重复扣减或重复创建流水。

### Phase H：查询、导出与提醒中心

- [ ] 实现日期、仓库、领用人、商品、尺码、类型、状态、去向组合筛选。
- [ ] 实现单据详情、审核记录、发放/归还和关联库存流水。
- [ ] 实现含两个固定工作表的 Excel 导出，并验证混领单关联。
- [ ] 实现待补手续、超期、待归还和同步异常管理员任务中心，按仓授权过滤。
- [ ] 实现工作日历后台和 3 个工作日计算测试。

### Phase I：历史迁移工具与演练

- [ ] 用 `lark-cli` 重拉六表只读快照并生成 SHA-256、revision、记录数和数量基线。
- [ ] 编写确定性转换器、幂等键、空白异常报告、历史顺序重建和产品映射测试。
- [ ] 在本地/测试 Base 完成重复迁移测试，证明第二次执行新增零记录。
- [ ] 生成正式迁移 dry-run 报告：目标表/字段、预计新增记录、余额和异常清单。

验证基线：指环 2,984 / 828 / 2,156；腕表 326 / 61 / 265；西湖零库存；三个历史腕表分别 27 / 42 / 68。

### Phase J：真实飞书增量建设与切换

- [ ] 使用 `lark-cli base +table-create --dry-run` 和字段 schema 文件预览两套 Base 的三个 V1 新表。
- [ ] 创建 `产品资料_V1`、`仓库库存余额_V1`、`库存流水_V1` 及必要视图，不改旧表结构。
- [ ] 批量导入产品、历史流水和余额；单批不超过 200，单表串行并逐批保存结果。
- [ ] 执行记录数、数量、产品尺码余额和幂等复跑对账。
- [ ] 上传 14 个产品各自的真实主图；缺图时允许完成数量迁移，但产品图片验收和正式上线切换不得标记完成。
- [ ] 短时冻结旧表人工写入，完成最终增量迁移和零差异对账。
- [ ] 切换系统映射到 V1 表，旧表设置只读归档，保留现有停用工作流和仪表盘。

回滚点：在切换映射前可直接停止；切换后若失败，暂停 worker/发放入口并退回旧表读取映射，绝不删除新表已写记录。

### Phase K：全量验收与交付

- [ ] 执行前后端 lint、typecheck、unit、integration、e2e、build。
- [ ] 使用 Playwright 覆盖桌面和移动端二维码申领、混领、审核、发放、补手续、查询与导出。
- [ ] 检查所有角色/仓库越权路径、CSRF、OAuth state、幂等和敏感日志。
- [ ] 执行生产样本 smoke test 和迁移后飞书定向回读。
- [ ] 运行 Trellis 全量检查、`git diff --check`，确认无密钥、一次性登录 token、快照个人信息或临时缓存进入 Git。
- [ ] 输出部署说明、环境变量清单、迁移报告、对账报告、管理员操作说明和回滚说明。

## 3. 关键测试矩阵

- 单据：正常/临时/线下 × 指环/腕表/混领 × 单条/多条。
- 权限：普通员工、单仓管理员、双仓管理员、系统管理员、外租户/停用员工。
- 库存：足够、不足、并发、重复请求、审核预占、取消、调拨、归还、盘点。
- 同步：成功、部分成功、超时、限流、字段漂移、权限错误、重启、人工重试。
- 迁移：空白记录、缺失人员/去向/类型、同日顺序、重复批次、余额差异。
- 页面：桌面/移动、长产品名、图片失败、零库存、历史停用、含待同步变动。
