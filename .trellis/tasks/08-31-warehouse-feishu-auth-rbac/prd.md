# 飞书登录与仓库权限

## Goal

实现公司飞书唯一登录、首位系统管理员一次性初始化、三角色和仓库级授权，为后续全部库存与领用接口提供可信身份、可复用的服务端权限判断和完整审计边界。

## Background

- 前置子任务 `08-31-warehouse-foundation-domain` 已完成并归档，现有数据库已包含用户、角色、仓库、仓库授权和审计基础表。
- 飞书只负责认证访问者身份；本系统负责会话、角色、仓库授权和业务审计。
- 普通浏览器走飞书 OAuth，飞书客户端内网页走免登授权码；两条入口最终进入同一身份解析与本地会话流程。
- 本任务不使用 `lark-cli`。真实飞书 Base 在第 7 个子任务前继续保持只读。

## In Scope

- 普通浏览器 OAuth 发起、回调、state 一次性消费和站内安全回跳。
- 飞书客户端免登授权码提交，并与 OAuth 入口复用同一身份服务。
- 校验允许租户、应用可用范围和员工在职状态；不合格身份不得创建或刷新本地会话。
- 首次合法登录幂等创建或更新本地用户，默认授予普通领用人角色。
- 通过稳定飞书用户 ID 与 tenant key 完成首位系统管理员一次性初始化，并保留永久初始化审计事件。
- 数据库存储的服务端会话、注销和当前用户接口；浏览器仅持有安全 cookie。
- `CLAIMANT`、`WAREHOUSE_ADMIN`、`SYSTEM_ADMIN` 三角色及西湖/余杭仓库授权矩阵。
- 可复用的认证守卫、角色守卫和仓库范围校验；仓库 ID 必须由服务端从 URL 或请求体重新解析并校验。
- 系统管理员维护用户角色和仓库授权的 API，并在同一事务中记录前后值审计。
- 最小登录/会话前端：飞书登录入口、客户端免登桥接、登录状态和受限页面跳转。

## Requirements

- 不提供本地密码、注册、账号审核、钉钉登录或匿名业务访问。
- 同一公司员工从 OAuth 或客户端免登入口登录时必须绑定到同一本地用户，不得因入口不同产生重复账号。
- 用户身份以允许 tenant 下的稳定飞书用户标识为准；姓名、头像和部门仅保存快照，不能用于账号匹配或提权。
- 外租户、超出应用可用范围、离职或本地停用用户不得建立新会话；既有会话在后续请求中也必须重新受本地状态约束。
- 首次合法登录默认具有 `CLAIMANT`；仓库管理员需同时具有 `WAREHOUSE_ADMIN` 和至少一个仓库授权；系统管理员默认拥有全部仓库权限。
- 初始管理员配置必须同时包含允许 tenant key 和稳定飞书 user ID。初始化只允许成功一次，之后修改环境变量不能自动为其他人提权。
- 初始管理员用户创建、角色授予、永久初始化标记和审计日志必须位于同一数据库事务，并能抵抗并发首次登录。
- 系统管理员可事务性更新用户角色与仓库授权。系统必须拒绝产生“仓库管理员无任何仓库范围”的无效组合，并防止移除最后一名有效系统管理员。
- OAuth return path 只允许已知站内路径。二维码入口 `/w/XIHU/apply` 与 `/w/YUHANG/apply` 登录后必须准确恢复，外部 URL、协议相对 URL 和未知仓库路径必须降级到安全首页。
- 会话 token 必须使用高熵随机值，数据库只保存不可逆摘要；cookie 使用 `HttpOnly`、`SameSite=Lax`，生产环境启用 `Secure`，注销后立即失效。
- API 错误使用稳定业务错误码，不向浏览器返回 App Secret、授权码、access token、完整飞书响应或内部堆栈。
- 所有权限修改、初始管理员授予和会话注销写入审计；登录失败只记录脱敏原因和 trace ID。

## Acceptance Criteria

- [ ] 外租户、无应用权限、飞书侧离职或本地停用员工登录均被拒绝，且数据库中不产生有效会话。
- [ ] OAuth 与客户端免登使用同一稳定身份时只得到一个本地用户，重复登录只刷新允许的资料快照与最后登录时间。
- [ ] 并发执行首位管理员登录时仅一个初始化事件成功，系统中只产生一个由配置初始化的系统管理员。
- [ ] 普通员工、单仓管理员、双仓管理员和系统管理员的角色/仓库权限矩阵自动化测试全部通过。
- [ ] 每个仓库级 API 都在服务端校验实际目标仓库；无权用户即使伪造前端状态或请求体也收到 `403`。
- [ ] OAuth state 只能消费一次；过期、篡改或重复回调均失败。
- [ ] OAuth 回跳保留合法二维码仓库上下文，外部地址和未知路径不能形成开放重定向。
- [ ] 会话 cookie 不暴露飞书 token；数据库不保存明文会话 token；注销和本地停用能阻止后续访问。
- [ ] 系统管理员修改角色/仓库范围后生成包含前后值的审计记录；不能移除最后一名有效系统管理员。
- [ ] 单元测试、PostgreSQL 集成测试、lint、typecheck、build、`git diff --check` 和敏感信息检查全部通过。
- [ ] 登录与权限实现不调用 `lark-cli`，不创建、修改或迁移真实飞书 Base。

## Out of Scope

- 飞书机器人、即时消息、个人提醒和审批流。
- 飞书通讯录离职事件订阅；本任务只消费登录时可验证的在职状态并预留后续状态同步边界。
- 商品、图片、库存查询、二维码生成和完整领用业务页面。
- 真实 Base 表结构、附件、库存同步、历史迁移与对账。
- 面向生产环境的飞书开放平台人工配置、域名备案、密钥录入和最终回调白名单发布；代码与环境变量契约会在本任务完成。
