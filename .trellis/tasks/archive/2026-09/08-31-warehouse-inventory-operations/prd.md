# 归还、调拨、盘点与提醒

## Goal

在正常领用、临时领用和线下登记已经形成可追溯出库事实的基础上，补齐采购/其他入库、分批实物归还、双仓调拨、盘点调整、工作日历维护和统一管理员任务中心。所有库存数量变化都必须由本地 PostgreSQL 原子事务生成业务记录、逐明细库存流水、outbox 和审计记录，不允许通过直接修改余额绕过流水。

## Background

- 前五个子任务已经合并到 `main`，现有系统具备 Vue/Nest/PostgreSQL 基线、飞书登录与仓库级 RBAC、商品和双仓库存查询、正常领用、临时领用、线下登记及本地 outbox。
- `InventoryTransactionExecutor` 已支持按稳定库存键排序锁行和批量库存变动，`InventoryService` 已提供原子 `transferBatch`；本任务应复用和收敛这些能力，而不是在控制器中直接更新余额。
- Prisma 已预留 `INBOUND`、`RETURN`、`TRANSFER_OUT`、`TRANSFER_IN`、`STOCKTAKE_GAIN`、`STOCKTAKE_LOSS` 流水类型，以及 `ReturnObligation`、可多条 `ReturnRecord`、`PARTIAL` 归还状态、`WorkCalendarDay` 和 `AdminTask`。
- 临时领用提交时已经保存确定的上海时区三工作日截止时间，并可生成待补手续/超期待办；本任务将其纳入统一任务中心并提供工作日历后台。
- 当前附件能力只有飞书商品图片的只读代理，没有通用上传接口、盘点附件数据模型或附件存储权限链路；盘点图片必传会扩大本子任务的基础设施范围。
- 真实飞书 Base 写入、outbox 消费、员工离职事件接入和历史迁移属于第 7 个子任务。本任务只完成本地领域触发、扫描器和待同步记录，不修改真实飞书 Base。

## Requirements

### R1. Shared inventory invariants

- 所有写操作必须要求稳定的 `Idempotency-Key`；相同键和相同命令返回原结果，相同键配不同命令返回 `IDEMPOTENCY_CONFLICT`。
- 所有数量必须为安全整数；入库、归还和调拨数量必须为正，盘点以非负实际盘点数量为输入。
- 一次多明细操作必须在同一 PostgreSQL 事务中全成或全败；任一明细无效、库存不足、越权或写入失败时不得留下部分业务记录、流水、余额、outbox、任务或审计。
- 每次有效库存变化必须生成唯一业务单号、逐明细 `InventoryMovement`、outbox 和审计记录；任何 API、服务或后台任务均不得直接改写库存余额。
- 真实库存立即通过本地待同步变动反映；飞书同步失败不得回滚已经确认发生的入库、归还、调拨或盘点事实。

### R2. Purchase and other inbound

- 获授权仓库管理员可为其授权仓库登记采购入库或其他入库；系统管理员默认可处理全部仓库。
- 一张入库单锁定一个仓库，可包含多个商品/规格明细，并保存入库类型、发生时间、操作人和必填备注/来源说明。
- 提交后直接完成本地入库并逐明细生成 `INBOUND` 正流水，不创建审批、预占或归还义务。
- 采购/其他入库只能选择当前有效的商品和规格；历史停用商品的既有库存仍可查询、调拨、归还和盘点，但不得通过普通新增入库继续补货。

### R3. Physical return

- 归还入口只处理已有 `ReturnObligation`，不得用自由入库伪装领用归还。
- 到达预计归还日期或检测到员工离职只创建/升级管理员待归还任务，不自动增加库存，也不自动完成归还义务。
- 仓库管理员确认实际收到物品时选择回库仓库和本次各规格归还数量；回库仓库必须在其授权范围内，可以与原出库仓库不同。
- 支持同一归还义务分批回库；每次确认生成独立 `ReturnRecord` 和 `RETURN` 正流水，累计数量不得超过应归还数量。
- 尚未全部归还时义务状态为 `PARTIAL`，全部归还后为 `COMPLETED`；对应待归还任务只有在相关义务全部完成后才完成。
- 本任务不开放无实物回库的免除/核销入口；损坏、遗失或无需再追缴的处置另行形成明确规则后实施。

### R4. Departure trigger

- 提供可复用的本地离职触发领域服务：按稳定用户身份查找仍未完成且触发方式为 `DEPARTURE` 的归还义务，并幂等创建红色待归还任务。
- 系统管理员可以在飞书同步异常时手动标记离职触发，必须填写原因并保留审计记录。
- 第 7 个子任务接入飞书员工状态同步或事件后，只调用本任务的领域服务，不得重复实现归还或直接回库逻辑。

### R5. Warehouse transfer

- 调拨用于余杭仓和西湖仓之间的库存移动，一张调拨单包含来源仓、目标仓和多个商品/规格明细。
- 操作人必须同时拥有来源仓和目标仓权限，或为系统管理员；单仓管理员不得借调拨修改未授权仓库。
- 调拨提交后在一个本地事务中为每个明细生成关联同一调拨 ID 的 `TRANSFER_OUT` 和 `TRANSFER_IN` 流水。
- 来源仓必须有足够可用库存；调拨不创建预占，不允许来源仓和目标仓相同，调拨前后两仓合计库存必须守恒。

### R6. Stocktake

- 仓库管理员只能盘点其授权仓库，系统管理员可盘点全部仓库。
- 盘点以指定仓库和每个规格的实际盘点数量为输入，系统锁定余额后计算与当前有效在库数量的差额。
- 正差额生成 `STOCKTAKE_GAIN`，负差额生成 `STOCKTAKE_LOSS`；零差额保留盘点业务记录与审计，但不生成零值库存流水或 outbox。
- 盘亏必须再次校验不会使有效在库量为负；同一批盘点的全部明细全成或全败。
- 每次盘点必须填写文字差异原因；V1 不要求图片附件，也不新增通用文件上传链路。

### R7. Work calendar

- 仅系统管理员可以新增、修改或删除 `WorkCalendarDay` 显式覆盖，日期唯一，内容包括日期、是否工作日和可选说明。
- 未配置日期继续按周一至周五为工作日、周六周日为非工作日；显式节假日和调休覆盖周历默认值。
- 日历修改只影响修改后新计算的期限；已经保存到临时领用和管理员任务上的截止时间保持不变，避免静默改变历史 SLA。
- 工作日历的新增、修改和删除必须留审计；普通读取不生成审计日志。测试覆盖跨长假、跨年、周末调休和重复日期冲突。

### R8. Administrator task center and scanners

- 管理员任务中心统一展示待补手续、补手续超期、待归还、归还超期及后续同步异常任务，并按状态、严重级别、类型和仓库筛选。
- 仓库管理员只能读取和处理其授权仓库的任务；系统管理员可查看全部任务。未绑定仓库的全局任务仅系统管理员可见。
- 任务中心不提供破坏业务不变量的通用“完成”按钮：待补手续由资料提交完成，待归还由实际回库完成，同步异常由后续同步处理完成。
- Worker 提供可重复执行的扫描：将到期的指定日期归还义务创建为 `RETURN_DUE`，逾期未归还升级为红色 `RETURN_OVERDUE`；相同业务对象不得重复创建开放任务。
- 提醒只进入网页管理员任务中心，不发送飞书机器人、短信、邮件或个人站内消息，也不冻结领用人的后续申请。

### R9. API, frontend and visibility

- 新增管理员库存业务 API 和页面，至少覆盖入库、归还、调拨、盘点、工作日历和管理员任务中心。
- 所有仓库相关接口都必须根据请求内实际仓库重新校验授权，不能只依赖前端隐藏入口。
- 商品选择器复用现有商品/库存投影；归还入口从归还义务和领用单详情进入，不能自由填写无法关联原单的人员或商品。
- 本人单据详情展示每个规格的应归还、已归还、剩余数量和归还记录；管理员可从任务中心进入对应处理页面。
- 新页面继续使用当前 `shadcn-vue` 与项目设计 token，只保留功能性文本，不使用蓝紫夜间模式、米白暖橙复古 serif、大圆角卡片、嵌套卡片或装饰性阴影。
- 桌面 `1440x900` 与移动端 `390x844` 不得出现文本遮挡或文档级横向溢出；异步路径必须有加载、错误、空状态和防重复提交反馈。

## Acceptance Criteria

- [x] AC1：授权管理员可提交多明细采购/其他入库，库存立即整单增加，并产生逐明细入库流水、outbox 和审计。
- [x] AC2：日期到达、归还逾期或员工离职只幂等创建/升级管理员任务，不自动增加库存或完成归还义务。
- [x] AC3：管理员确认实物回库后才生成归还记录和正流水；支持分批归还且累计数量不能超过应归还数量。
- [x] AC4：归还任务在相关义务全部完成后自动完成；本人和管理员详情可核对每个规格的应归还、已归还和剩余数量。
- [x] AC5：调拨要求同时拥有两仓权限，任一明细库存不足时整单失败；成功时一出一入关联同一调拨 ID 且两仓总量守恒。
- [x] AC6：盘点按实际数量生成盘盈或盘亏流水；零差异不生成零值流水，所有结果均保留盘点记录、原因和审计。
- [x] AC7：入库、归还、调拨和盘点的重复请求返回原结果；相同幂等键配不同命令被拒绝且不产生第二次库存变化。
- [x] AC8：工作日历支持节假日和调休覆盖，跨长假/跨年计算正确；日历修改不重写已保存截止时间。
- [x] AC9：统一管理员任务中心包含待补、超期未补、待归还和归还超期，仓库管理员只能看到授权仓任务，系统管理员可查看全部。
- [x] AC10：不存在无流水修改余额的控制器或服务入口；所有多明细操作在 PostgreSQL 中全成或全败。
- [x] AC11：共享契约、数据库集成、Nest HTTP、Worker、Vue 单元测试和双视口浏览器验收覆盖全部流程；根级 lint、typecheck、test、integration、build、Prisma validate、format check 和 `git diff --check` 通过。

## Out of Scope

- 真实飞书 Base 写入、outbox 消费、同步重试、同步异常处置和历史迁移。
- 飞书员工离职事件/通讯录状态的真实接入；本任务只提供本地触发服务和系统管理员手动兜底。
- 归还义务免除、报损、赔偿、维修、借用续期和跨单合并归还。
- 条码/序列号级单件追踪、打印、扫码盘点和移动端相机上传。
- 盘点图片附件上传与存储；V1 以必填文字差异原因和审计记录作为凭证。
- Excel 导出和复杂组合查询。
