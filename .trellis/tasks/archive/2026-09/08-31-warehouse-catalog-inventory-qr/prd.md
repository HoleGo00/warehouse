# 商品图片、库存查询与仓库二维码

## Goal

实现可扩展的商品/规格管理、所有员工可访问的双仓库存查询、飞书附件图片展示契约，以及西湖仓/余杭仓稳定扫码入口，为后续正常领用表单提供唯一的商品选择和库存读取来源。

## Background

- 工程基线、PostgreSQL 领域模型、库存事务和本地飞书 RBAC 已完成；真实 OAuth 回调验收按用户决定延期到服务器部署后，不阻塞本任务使用现有会话守卫和自动化测试继续开发。
- Prisma 已包含 `ProductCategory`、`Product`、`ProductVariant`、`ProductImageRef`、`Warehouse` 和 `InventoryBalance`；种子已建立 10 款智能指环、健康腕表和 3 个历史停用腕表，以及指环 6# 至 13# 规格。
- 库存展示口径固定为：有效现存数量 = 飞书已确认数量 + 待同步变动；可用数量 = 有效现存数量 - 活动预占量。
- 当前仓库尚无产品图片引用，真实飞书 Base 写入和 `lark-cli` Gateway 按 Epic 顺序只能在第 7 个子任务开始。
- 当前 Web 只有认证工作台，没有路由、商品页面、库存页面或二维码页面。
- 2026-09-04 用户批准：本任务完成图片契约、缺图状态和本地自动化/视觉验收；14 张真实主图的飞书附件上传留到第 7 个同步迁移任务，生产域名二维码与正式图片验收留到第 9 个集成切换任务。

## Requirements

### R1. 商品与规格

- 共享 contracts 定义商品管理、库存查询、图片元数据和仓库入口的请求/响应 schema；API 和 Web 不重复声明传输类型。
- 系统管理员可创建和更新商品名称、类别、规格模式和状态；新增指环自动建立 6# 至 13# 规格，新增腕表只建立一个无尺码规格，不需要修改数据库结构或业务代码。
- `ACTIVE` 商品用于后续申领选择；`INACTIVE` 和 `INACTIVE_HISTORICAL` 只在库存查询与历史对账中可见，不得进入申领选择接口。
- 现有 3 个历史腕表必须分别保留为独立商品，并显示“历史停用”状态。
- 已产生库存或业务引用的商品/规格不得物理删除；V1 通过状态停用。

### R2. 图片引用与展示

- 飞书附件字段仍是正式产品图片的唯一来源，本地数据库只保存附件 token、主图/详情图类型、顺序、文件名和刷新时间。
- 浏览器只访问本系统图片地址，不直接获得飞书临时下载 URL、CLI 输出或应用凭据。
- 图片内容读取通过可替换 provider 边界实现；API 控制鉴权、内容类型、短时私有缓存和稳定错误响应，不在控制器中执行 CLI。
- 没有主图的商品必须明确返回 `imageReady=false` 并显示“未配置主图”状态，不使用通用商品图冒充。
- 新建商品默认不可申领；只有状态为 `ACTIVE`、规格启用且主图就绪的商品才进入后续申领选择接口。

### R3. 双仓库存查询

- 所有已登录公司员工均可查询西湖仓、余杭仓和两仓汇总，不因普通领用人、仓库管理员或系统管理员角色隐藏库存数量。
- 查询支持按仓库和商品大类筛选，返回商品、规格、图片状态、飞书确认数量、待同步变动、有效现存数量、预占数量、可用数量和同步标识。
- 指环在页面中按“款式 × 6# 至 13#”矩阵展示；腕表按产品列表展示且不出现尺码输入。
- 任一规格存在非零待同步变动时，页面显示“含待同步变动”，但不暴露内部错误堆栈。
- 历史停用腕表库存继续可见并带状态标识。

### R4. 仓库入口与二维码

- 路由使用稳定仓库入口 `/w/:warehouseCode/apply`，仅接受 `XIHU` 和 `YUHANG`；二维码只编码部署后的 Web 公网地址和该路径，不包含账号、库存或 token。
- 扫码用户未登录时进入飞书登录，认证 return path 必须保留仓库路径；登录后仍锁定原仓库。
- 页面明确提供“正常领用”和“临时领用”两个后续流程入口；本任务不实现申请提交。
- 系统按配置的 `WEB_PUBLIC_URL` 生成二维码内容和可下载 SVG；生产环境未配置正式 HTTPS 域名时不得将本地二维码当作正式物料。

## Acceptance Criteria

- [x] AC1：系统管理员可新增/更新指环或腕表商品；指环自动产生 8 个尺码规格，腕表只产生无尺码规格。
- [x] AC2：库存接口和页面准确展示西湖、余杭及两仓汇总；计算口径与共享 `calculateAvailability` 一致。
- [x] AC3：指环使用款式尺码矩阵，腕表使用无尺码列表，并覆盖桌面与移动端布局。
- [x] AC4：3 个历史停用腕表在库存查询中可见且有明确标识，申领选择接口不返回任何停用商品或规格。
- [x] AC5：待同步变动会改变有效现存/可用数量并显示同步标识，普通员工可看到与管理员一致的数量。
- [x] AC6：产品响应只暴露本系统图片 URL；缺主图时显示明确缺图状态，不使用假图。
- [x] AC7：`/w/XIHU/apply` 与 `/w/YUHANG/apply` 均能在登录前后保留仓库上下文，非法仓库值被拒绝。
- [x] AC8：二维码 SVG 只包含配置后的稳定仓库 URL，可下载且不包含敏感参数。
- [x] AC9：合同/领域单测、API HTTP 测试、PostgreSQL 集成测试、前端单测、桌面和移动浏览器验收通过。
- [x] AC10（延期门槛）：第 7 个任务完成 14 张真实主图上传，第 9 个任务使用生产域名完成正式图片和二维码验收；本任务只证明缺图保护与代理契约，不能宣称正式图片验收完成。

## Out of Scope

- 正常领用、临时领用、审核、发放、补手续和库存扣减。
- 真实飞书 V1 新表创建、历史迁移、附件上传和 Base 写入。
- 使用通用占位图、外部对象存储或把本地文件路径作为生产图片地址。
- 最终生产二维码印刷物料；正式域名和 HTTPS 部署在集成切换任务完成。
