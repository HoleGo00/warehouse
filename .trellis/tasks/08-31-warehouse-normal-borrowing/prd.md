# 正常领用审核与发放

## Goal

让公司员工从固定仓库二维码进入正常领用表单，提交一张可混合智能指环和智能腕表的整单申请，并由获授权仓库管理员完成一道审核、库存预占和确认发放。库存只在实际发放时减少，所有审批、取消、发放和库存变化均可追溯且可安全重试。

## Background

- 前置子任务已经提供飞书唯一登录、三角色及仓库级 RBAC、商品与规格目录、双仓可用库存查询、稳定仓库二维码入口，以及支持整单预占、释放和消费预占的库存事务能力。
- 当前 `requests`、`request_items`、`approval_records`、`fulfillments`、`return_obligations` 和库存相关表已存在，但尚无正常领用领域服务、HTTP 契约和可用页面。
- 本子任务是 Epic 第 4 项；临时领用、线下登记、实际归还、查询导出和飞书真实同步仍由后续子任务负责。

## In Scope

### 1. 员工提交与查看

- 二维码仓库上下文必须锁定到 `XIHU` 或 `YUHANG`，页面不得允许用户把明细改投另一仓库。
- 登录员工可以查看二维码对应仓库的可领用商品、规格和当前具体可用数量，并提交正常领用单。
- 一张单可以同时包含智能指环和智能腕表，但所有明细必须属于同一仓库，并共用领用类型、用途/对象、最终去向、备注和归还规则。
- 只允许选择当前可申领的启用商品和启用规格；历史停用商品不得加入新申请。
- 提交时后端重新校验明细、商品状态、仓库和可用库存；校验通过后状态进入 `PENDING_APPROVAL`，只记录申请，不创建预占或库存流水。
- 员工可以查看本人申请列表与详情；被退回的申请允许修改整单资料和明细后重新提交。

### 2. 条件字段

- 领用类型为内部领用、外部赠送、销售或展品。
- 用途/对象与最终去向为必填业务信息；备注为可选。
- 外部赠送与销售固定为无需归还，不接受预计归还日期。
- 展品固定为指定日期归还，并必须填写未来或当天的预计归还日期。
- 内部领用可以选择无需归还、指定日期归还或员工离职时归还。
- 内部领用选择指定日期归还时必须填写预计归还日期；选择离职时归还时使用当前申请人的已绑定飞书员工身份，不填写固定日期。

### 3. 一道审核与整单预占

- 只有系统管理员或拥有申请所属仓库权限的仓库管理员可以查看和处理该仓待审核单。
- 审核必须按整单批准或整单退回，不提供明细级部分处理。
- 批准时在同一数据库事务中锁定申请与全部库存行，再次校验商品状态和可用库存；全部满足后才创建一批活动预占、写审批记录和审计，并把状态改为 `PENDING_RELEASE`。
- 任一明细不足、失效或不合格时不得创建部分预占；管理员应整单退回并填写审核意见，申请状态改为 `REJECTED`。
- 重复审核请求必须返回首次结果，不能重复预占或生成第二条审批结果。

### 4. 取消与发放

- 发放前取消必须填写原因，并在同一事务中释放整批活动预占、更新状态和写入审计；无预占的待审核单取消时不改变库存。
- 申请人可以取消本人处于 `PENDING_APPROVAL` 或 `PENDING_RELEASE` 的申请；审核通过后的自行取消同样必须原子释放整批预占。
- 对应仓库管理员或系统管理员可以取消 `PENDING_RELEASE` 申请；待审核申请应通过审核退回而不是管理员取消。
- 只有 `PENDING_RELEASE` 状态可以确认发放；待审核、已退回、已取消或已完成的申请不得发放。
- 确认发放必须在同一事务中消费完整预占、为每条明细创建 `ISSUE` 负库存流水、更新本地有效库存、创建 outbox、写发放记录和审计，并把申请状态改为 `COMPLETED`、同步状态改为 `PENDING`。
- 发放明细必须与活动预占完全一致；不支持部分发放。
- 对需要归还的申请，发放事务同时按明细创建归还义务；本子任务不实现实际回库或到期提醒。
- 重复发放请求返回首次结果，不得产生第二批库存流水、第二个发放记录或重复归还义务。

### 5. 页面

- 仓库入口页启用“正常领用”入口，跳转到锁定仓库的申请页；“临时领用”继续显示为后续能力。
- 员工端提供正常领用表单、提交结果、本人申请列表、详情、被退回申请的修改重提，以及符合策略的取消操作。
- 管理端提供授权仓库范围内的待审核与待发放队列、整单详情、批准、退回、取消和确认发放操作。
- 所有异步操作提供 loading、disabled、成功和错误反馈；桌面与移动端不得产生页面级横向溢出。

## Out of Scope

- 临时领用、补手续和线下登记。
- 实物归还确认、待归还到期或离职提醒、入库、调拨和盘点。
- Excel 导出、完整组合查询和同步异常管理后台。
- 真实飞书 Base 写入、outbox worker 消费、历史迁移和生产切换；本任务只可靠地产生本地流水与待同步 outbox。
- 多级审批、部分审批、部分预占、部分发放和跨仓申请。
- 为其他员工代提正常领用单。

## Acceptance Criteria

- [ ] AC1：员工从两个稳定二维码入口进入时，仓库上下文保持不变；非法仓库代码不能提交申请。
- [ ] AC2：正常领用表单可以混合添加启用的指环和腕表规格，但不能添加停用商品、停用规格、重复规格或另一仓库明细。
- [ ] AC3：四类领用及归还字段按规则校验；展品缺少预计日期、销售或赠送携带归还字段、内部领用字段组合非法时均被拒绝。
- [ ] AC4：提交只创建 `PENDING_APPROVAL` 申请；审核前库存余额、活动预占和库存流水均不变化。
- [ ] AC5：库存足够时，授权管理员批准整单后只增加活动预占，申请进入 `PENDING_RELEASE`，实际库存与流水仍不变化。
- [ ] AC6：任一明细库存不足或商品失效时批准整单失败，申请状态、所有库存行和预占均保持原样；并发批准不会超卖。
- [ ] AC7：退回记录审核人、时间、意见及状态变化；员工可修改同一申请后重新提交，旧审批记录继续保留。
- [ ] AC8：申请人可取消本人待审核或待发放申请；授权管理员可取消待发放申请。所有取消记录操作人、时间和原因，存在活动预占时整批释放，不存在部分释放。
- [ ] AC9：确认发放消费完整预占，逐明细生成 `ISSUE` 负流水与一个 outbox 聚合任务，申请进入 `COMPLETED`，本地可用库存立即反映变化。
- [ ] AC10：同一幂等键重试提交、重提、审核、取消或发放返回同一结果；换参数复用幂等键产生冲突，重复发放不产生第二次库存变化。
- [ ] AC11：系统管理员可以处理两仓；仓库管理员只能查看和处理已授权仓库；普通员工只能查看、修改或取消本人符合状态规则的申请。
- [ ] AC12：需要归还的申请仅在发放成功后按明细创建归还义务；取消或退回不创建归还义务，也不提前增加库存。
- [ ] AC13：员工与管理页面在 1440x900 和 390x844 下可完成主流程，键盘焦点、加载、错误、空状态和长商品名均可识别且无页面级横向溢出。
- [ ] AC14：共享契约、lint、typecheck、单元测试、PostgreSQL 集成测试、构建、`git diff --check` 和浏览器验收全部通过。
