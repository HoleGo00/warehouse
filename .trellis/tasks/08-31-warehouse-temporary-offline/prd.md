# 临时领用与线下登记

## Goal

在正常领用基础上补齐两条已确认发生实物出库的路径：员工通过仓库二维码发起临时领用并立即扣减库存，之后补齐资料接受一道审核；获授权仓库管理员可以代录信息完整的线下领取并直接完成整单出库。两条路径都必须保留准确的人员、仓库、商品、库存流水、同步任务和审计记录。

## Background

- 前置子任务已经实现 Vue/Nest/PostgreSQL 基线、飞书登录与仓库级 RBAC、商品与双仓库存查询、二维码入口，以及正常领用的提交、审核预占、取消和发放。
- 现有 `RequestOrigin` 已包含 `ONLINE`、`OFFLINE` 和 `EXPRESS`，`RequestStatus` 已包含 `PENDING_PAPERWORK`；`InventoryTransactionExecutor` 已支持同一数据库事务内的整批库存流水与 outbox。
- 当前 `Request.type` 为必填，但临时领用首次提交时业务类型尚未补齐，因此需要向前兼容迁移为可空；已有正常领用和线下登记仍必须保存非空类型。
- `WorkCalendarDay`、`AdminTask`、`PAPERWORK_REQUIRED` 和 `PAPERWORK_OVERDUE` 已存在于数据模型，但尚无工作日计算、待补手续任务或前端队列实现。
- 当前本地员工档案只在员工成功登录后创建，仓库管理员尚无员工搜索接口；真实飞书通讯录字段权限和生产 OAuth 回调仍处于延期状态。
- 用户已确认 V1 线下登记只选择已经登录、已有本地档案且当前有效的员工；未建档员工必须先完成一次登录，本任务不调用飞书通讯录搜索。

## Requirements

### R1. Shared invariants

- 所有写操作必须要求稳定的 `Idempotency-Key`；相同键和相同命令返回原结果，相同键配不同命令返回 `IDEMPOTENCY_CONFLICT`。
- 每张单只能对应一个二维码锁定仓库，可以混合智能指环和智能腕表；同一规格不得重复，数量必须为正安全整数。
- 历史停用商品和停用规格不得用于临时领用或线下登记。
- 任一明细不可用、库存不足或事务内写入失败时，整张单失败，不得留下部分请求、部分流水、部分 outbox 或部分库存扣减。
- 本任务只创建本地待同步 outbox，不写入真实飞书 Base；真实同步和历史迁移仍属于后续子任务。

### R2. Temporary borrowing submission

- 员工从 `/w/:warehouseCode/apply` 进入临时领用，仓库由路由锁定，领用人由当前会话锁定。
- 首次提交只填写商品明细；不得要求领用类型、用途/对象、最终去向、备注或归还规则。
- 提交在一个 PostgreSQL 幂等事务中创建 `origin=EXPRESS`、`status=PENDING_PAPERWORK` 的请求和快照明细，立即创建逐明细 `ISSUE` 流水、outbox、出库执行记录、审计记录及待补手续管理员任务。
- 临时领用不创建库存预占；提交成功后的本地可用库存必须立即反映已发生的出库。
- 提交失败或相同命令重试不得创建第二张请求、第二批流水或第二个待办。
- 临时领用发生后不提供普通取消或直接撤销出库动作；实物退回由后续“归还、调拨、盘点与提醒”子任务处理。

### R3. Paperwork completion and review

- 领用人只能为自己的临时领用补充完整资料：领用类型、用途/对象、最终去向、备注、归还方式和按规则出现的预计归还日期。
- 仓库、领用人、已出库商品明细和数量在补手续阶段锁定，不允许通过编辑手续静默改变已经发生的库存事实。
- 补齐并提交后，状态从 `PENDING_PAPERWORK` 或 `REJECTED` 进入 `PENDING_APPROVAL`，原待补手续管理员任务完成。
- 授权仓库管理员执行一道后补审核：通过后进入 `COMPLETED` 并按完整资料创建必要的归还义务；资料不合格时必须填写意见并进入 `REJECTED`，前端对临时领用显示为“待补正”。
- 退回补正继续沿用首次临时领用的原截止时间，不重新获得三个工作日。
- 补手续、退回补正和审核均不得创建库存预占、库存流水、第二个出库记录或第二个 outbox。

### R4. Three-working-day deadline

- 截止时间为临时领用提交日之后第三个工作日 `23:59:59`，使用 `Asia/Shanghai`；提交日不计入三个工作日。
- 工作日判断以 `WorkCalendarDay` 显式配置为最高优先级；未配置日期按周一至周五为工作日、周六周日为非工作日。
- 临时领用提交时保存确定的 `dueAt` 并创建 `PAPERWORK_REQUIRED` 管理员任务。
- 管理员待补手续队列必须按实际仓库授权过滤，并明确区分未超期和超期；超过 `dueAt` 后显示红色超期状态，但请求仍保持待补手续/待补正流程，不冻结领用人。
- 本任务实现临时领用需要的期限计算、任务创建/完成和可重复执行的超期升级；通用工作日历维护页面、周期调度器及集中管理员提醒中心属于下一子任务。

### R5. Offline registration

- 线下登记只允许仓库管理员处理其授权仓库，系统管理员默认拥有全部仓库权限。
- 实际领用人只能从已有本地档案且当前有效的员工中搜索和选择；未建档员工需先登录一次。
- 管理员必须选择实际领用人，并一次填写完整的领用类型、用途/对象、最终去向、备注、归还规则、预计归还日期和商品明细。
- 缺少任何条件必填资料时接口拒绝，不允许以残缺线下登记绕过临时领用的补手续和审核流程。
- 提交在一个 PostgreSQL 幂等事务中创建 `origin=OFFLINE`、`status=COMPLETED` 的请求和快照明细，立即创建逐明细 `ISSUE` 流水、outbox、出库执行记录、必要的归还义务和审计记录。
- 线下登记不创建审批记录或库存预占；记录必须同时投影实际领用人与代录管理员。

### R6. API and visibility

- 员工本人列表和详情必须同时展示正常领用、临时领用和由管理员为其代录的线下登记，并显示明确来源。
- 管理员请求页面增加独立的待补手续/待补正队列，以及线下登记入口；所有列表和写接口都按请求实际仓库重新授权。
- 临时领用允许动作由服务端投影，至少区分补手续、补正和后补审核；前端不得仅凭角色或状态自行推断权限。
- API 保持稳定错误结构，并覆盖认证失败、仓库越权、非本人补手续、非法状态迁移、库存不足和幂等冲突。

### R7. Frontend behavior and design

- 启用二维码入口中的临时领用选项，新增锁仓临时领用页面；复用当前可选商品与库存数据，提交时仍由后端重新校验。
- 新增完整资料表单复用正常领用的业务字段规则，但不得允许修改临时领用的已出库明细。
- 新增管理员线下登记页面，实际领用人必须通过受控选择器确定，不能自由填写一个无法关联用户的姓名字符串。
- 本任务是新增的重要前端功能，首次引入 `shadcn-vue`、Tailwind、`@` 别名和 `components.json`，先生成本任务实际使用的最小共享控件，不做无关的全站重写。
- 新增页面遵守前端设计规范：只保留功能性文本，禁止蓝紫夜间模式、米白暖橙复古 serif 风格、大圆角卡片、嵌套卡片、无目的边框和装饰性阴影。
- 桌面 `1440x900` 与移动端 `390x844` 均不得出现文本遮挡或文档级横向溢出；所有异步路径必须有加载、错误、空状态和防重复提交反馈。

## Acceptance Criteria

- [x] AC1：临时领用只提交锁定仓库、当前领用人与一组商品明细即可成功；成功后库存立即整单扣减并进入“待补手续”。
- [x] AC2：临时领用任一明细库存不足、不可用或事务失败时整单回滚；相同幂等键重试不产生第二次扣减、流水、outbox 或待办。
- [x] AC3：领用人可补齐本人临时领用资料，但不能修改仓库、人员或已出库明细；补齐后进入一道后补审核。
- [x] AC4：后补审核通过后完成请求并按资料创建归还义务；退回时进入“待补正”并保留意见和原截止时间；两种结果均不再次改变库存。
- [x] AC5：截止时间准确落在提交日之后第三个工作日的上海时区日末，显式节假日/调休配置覆盖默认周历。
- [x] AC6：管理员可按授权仓库查看待补手续、待补正和超期记录；超期显示红色但不限制领用人的其他申请。
- [x] AC7：授权管理员可完整代录线下领取；成功后请求直接完成并整单扣减，详情同时显示实际领用人和代录管理员，且无审批节点。
- [x] AC8：线下登记资料不完整、实际领用人无效、仓库越权或库存不足时失败且不留下部分库存变化。
- [x] AC9：本人列表/详情能区分线上正常、临时和线下登记来源，并只显示服务端允许的动作。
- [x] AC10：共享契约、PostgreSQL 集成、Nest HTTP、Vue 单元测试和双视口浏览器验收覆盖上述流程；根级 lint、typecheck、test、build、Prisma validate 和 `git diff --check` 全部通过。

## Out of Scope

- 真实飞书 Base 写入、outbox worker 消费、历史表迁移和生产切换。
- 实物归还、入库、两仓调拨、盘点调整、通用管理员任务中心和工作日历管理后台。
- Excel 导出、复杂组合查询和同步异常后台。
- 通过负数补偿、删除流水或直接改余额撤销已经发生的临时/线下出库。
