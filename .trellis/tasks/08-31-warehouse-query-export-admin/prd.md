# 业务查询、Excel 导出与管理后台

## Goal

让管理员按授权范围查询领用业务、下载可核对的 Excel，并在网页维护已登录员工的角色和仓库授权。复用已有商品、日历、待办和同步页面，不重建业务流程。

## Background

- 基线为 `main@53a27c4`；第 7 项已通过 PR #7 合并，前七项代码依赖满足。
- 总需求来源为 Epic `prd.md` 的 R9、R10，以及 AC13、AC14、AC20、AC21、AC26、AC29。
- 现有查询服务仅覆盖本人记录、详情、审核和补手续队列；人员权限更新已有后端接口，但没有对应管理页面。
- 三类领用流程均在业务事务中创建发放记录；详情已有审核和归还信息，需补关联库存流水的可见投影。
- 仓库级业务权限和全员库存数量可见是两回事，本任务不得改变已有全员库存查看权限。
- 代码及规格证据见 `research/planning-evidence-2026-09-09.md`。

## Requirements

### R1. 组合查询与详情

- 系统管理员查询全部仓库；仓库管理员只能查询授权仓库。未选择仓库表示“全部已授权仓库”，明确请求未授权仓库返回拒绝，不静默扩大范围。
- 支持日期范围、仓库、领用人、商品大类、产品/款式、尺码、领用类型、来源、流程状态、同步状态和最终去向组合筛选，并提供分页。
- 历史已停用产品和已停用领用人仍可作为历史业务的查询条件，但不扩大人员管理权限或允许再次领用停用产品。
- 商品大类、产品、尺码条件必须由同一条明细同时满足。列表每张命中单据只出现一次，显示“筛选明细数量”；单据详情仍展示授权范围内的完整单据、审核、发放、归还和库存流水。
- 查询只覆盖系统已有领用单，不把缺少领用单关联的旧库存流水伪造成领用申请。

### R2. 日期口径

- 默认按提交日期，可切换实际发放日期；查询和导出采用同一日期口径。
- 按 `Asia/Shanghai` 自然日计算起止范围，包含用户选择的首尾日期。
- 提交日期沿用现有单据提交时间语义；实际发放使用同事务发放记录，不用单据完成、审核、补手续或同步完成时间代替。
- 未发放单据不命中实际发放日期范围；显示空值，不伪造发放日期。

### R3. 双工作表导出

- 导出当前全部筛选结果，不只导出当前分页；固定且仅包含 `领用单汇总`、`商品明细` 两张工作表，以业务单号关联。
- 只导出命中商品条件的明细。汇总每单一行，数量仅为导出明细数量之和；整单流程状态仍按整单事实显示，不把筛选后的一部分误标为整单已同步。
- 两表采用同一数据库读取快照。文件记录筛选条件、日期口径和数据截至时间；数据截至后台任务开始读取时，不承诺冻结点击导出时的业务状态。
- 工作表保留主单、人员、仓库、审核、发放、归还、同步、商品、尺码、数量及业务来源等可追溯字段；缺失信息明确为空，不编造历史值。
- 自由文本按文本写入，不执行用户提供的公式或生成外链；中文、长文本和空结果均能导出有效文件。

### R4. 后台任务与文件生命周期

- 请求导出后立即返回任务，后台生成文件。提供排队、生成中、完成、失败、过期状态；生成期间可以离开页面，回来后查看自己的导出任务。
- 成功生成后 24 小时内可重复下载；到期立即拒绝下载，并在清理周期删除生成文件，保留不含完整导出内容的审计记录。到期后可重新导出。
- 创建、执行、发布和下载阶段检查身份及仓库权限；权限撤销后不得凭已生成文件继续下载。只有发起人可以下载自己的任务结果。
- 重复提交同一操作不得产生重复任务；服务重启可恢复排队和失去执行进程的任务，不发布半成品。
- 生成失败必须有可理解的错误；重新生成是独立导出，不延长旧文件有效期、不改写旧审计。
- 已批准的资源保护为单任务最多 100,000 条命中商品明细、单文件 64 MiB、300 秒、每人最多 2 个未完成任务；超过限制明确报错并要求缩小范围，绝不静默截断。

### R5. 人员权限及既有后台

- 新增人员权限页面，只供系统管理员查询已登录过的本地员工档案，授予/撤销角色并设置仓库范围。
- 继续保留普通领用人角色；仓库管理员至少授权一个仓库；系统管理员拥有全仓权限。角色变更记录前后值和操作人，不能移除最后一个有效系统管理员。
- 页面不能创建本地账号、设置密码、冒用飞书身份或手动改变员工在职状态。
- 复用现有商品/图片、工作日历、管理员待办、同步异常、幂等重试及对账页面；同步管理操作仍只对系统管理员开放。
- 飞书映射仅查看已脱敏的绑定状态，不提供网页修改 Base、表、字段映射或激活正式绑定。同步目标变更及正式激活归第 9 项受控切换，不将映射维护的完整能力标记为已实现。

## Acceptance Criteria

- [x] AC1：三类业务来源可组合筛选并分页，明确指定未授权仓库和跨仓详情请求被拒绝。
- [x] AC2：混领单筛选指环后，两张工作表均不计入腕表数量；汇总每单一行、明细多行，同单商品条件不跨明细拼接命中。
- [x] AC3：9 月 1 日提交、9 月 3 日发放的单据在两种日期口径分别归入对应日期；跨午夜、范围首尾和未发放情况正确。
- [x] AC4：临时领用后续补手续、审核和同步完成不改变实际发放日期；详情保留整单记录并可查看关联流水。
- [x] AC5：导出两表来自同一快照；生成期间并发审核/归还不能造成汇总与明细互相矛盾。
- [x] AC6：生成中普通 API 仍可响应，100,000 条合成明细可成功导出；超量、文件过大及超时失败不产生可下载的截断结果。
- [x] AC7：重复提交、进程中断和租约失效不会生成多个有效结果或发布半文件，完成后 24 小时过期，清理后审计仍在。
- [x] AC8：本人身份、当前仓库权限和文件有效期在下载时重新校验，账号停用、撤权、猜测任务标识和路径穿越均不能获取文件。
- [x] AC9：空结果仍有两个工作表；中文、长文本和公式样式文本保留为安全数据，数量列可计算。
- [x] AC10：系统管理员可在网页维护已登录员工角色和仓库范围；并发撤销最后管理员被拒绝，审计和重新加载后的权限一致。
- [x] AC11：商品/日历/待办/同步入口继续可用，同步重试复用原任务与幂等机制并留审计；映射没有新增写入口。
- [x] AC12：全仓质量检查、PostgreSQL 集成测试、真实下载文件回读和桌面/移动界面检查通过，明确区分模拟登录与生产 OAuth 验收。
